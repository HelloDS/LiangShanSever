# 亲友圈组织协议与规则缺口

阶段：第二版组织业务；原 Creator 地址外不改动。依据 `前端字段与源码证据.md` R004–R038，以及归档 `Client/archive/8.137.34.190/client/modules/club/assets/module_club.min.js` 的实际调用和消费。下述 JSON 为脱敏结构样例，不是原站在线抓包，也不代表测试已通过。

## 已确认的消费者

| 路由 | 字段与响应 | 权限/事务边界 |
| --- | --- | --- |
| club/getClubs | clubs 为按圈 ID 索引的对象；msgRedPoint 布尔 | 仅本人有效成员关系 |
| club/getClub | id → club | 当前成员；不是任意资源详情入口 |
| club/getClubMems | club_id → mems 为 UID 数组 | 本圈成员 |
| club/getRoles | club_id,uids → roles 按 UID 索引 | 本圈成员；管理员可查本圈待加入申请人，不允许借圈批量查任意玩家 |
| club/getClubConfig | config.only_manager_open_room 数值 0/1；is_manager/is_partner 布尔 | 本圈成员；is_manager 包含圈主和管理员，未实现合伙人时不得伪造身份 |
| club/setClubConfig | club_id,config.only_manager_open_room | 圈主/管理员；只允许已知字段 |
| club/apply、applyLeave | id | 本人申请；圈主不能通过退出绕开解散/退款 |
| club/getApplyList | id,page,limit → list.page,total_page,rows | 管理员；row 为 apply_role、apply_time，可选 partner_role |
| club/getApplyLeaveList | id → list 为 UID 到申请时间的对象 | 管理员 |
| club/reviewApply、reviewApplyLeave | id,targetUid,val；1 同意、2 拒绝 | 本圈管理权限；行锁、条件状态更新、成员唯一键、人数事务更新 |
| club/kick | id,targetUid | 圈主/管理员；管理员不能移除同级/圈主；不能踢本人 |
| club/setClubManager、removeClubManager | club_id,uid | 仅圈主；人数上限未确认时禁止新增管理员，不等于无限数量 |
| club/getClubMsgs | msgs 为 CSV 字符串数组 | 仅本人；名称禁止逗号/HTML 特殊字符的创建规则仍待创建流程落地 |
| club/getRoomList | list 对象、redPoints 对象、default_room 可空 | 本圈成员；第二版没有真实房间时为空 |
| room/getDefaultRoomConfig | config 可空 | 本圈成员；自动执行留第三版 |
| club/getClubZhanJi、getRoleZhanJi | zhanjis 数组、roles 对象 | 前者管理权限；后者本人成员范围；无对局事实为空 |

成员消费者的 `club_level=1` 为管理员、`2` 为普通成员；圈主由 club.owner 独立判定。`game_number/game_at` 仅代表真实对局事实，不能用登录数填充。

服务端推送使用原 cmd：club_apply、club_applyLeave、club_applyOk、club_applyLeaveOk、club_kick、clubConfigChange、clubManagerChange。配置变更必须带 config.only_manager_open_room；管理员变更必须带 member.uid、member.level（1/2）。引发变更的连接先排入唯一普通 ACK，再发推送。离线接收者以持久消息和下次查询恢复，推送不是组织权威源。

## 未确认项

- 创建圈的 need_card。源码说明是从个人转入圈钱包，解散时退还，不是直接销毁。不得默认免费、凭空配一个原站价格或返回成功绕过转入。
- 初始成员上限、管理员上限、升级上限及资源公式。当前服务端仅把每圈已确认的上限作为数据；未配置管理员上限时拒绝提升。10000 是接口/存储保护上限，不宣称原业务容量。
- 改名是否扣卡、解散退款接收人及各类已用/冻结资金处理；未确认前这些经济入口统一明确拒绝，不改变资产。
- 建设/合伙人归属和业绩规则、自动开房触发及 groupid 语义；不从路由名推导收益或审批权限。
- 旧接口不带请求号，重复审批只允许一次状态迁移，再次返回业务错误，避免旧客户端重复增加/减少人数。可重复转卡不能仅按同额短时间窗宣称精确幂等。

## 开发与验收约定

所有测试圈必须明确标记 is_test；隔离数据库可建立“既有圈”夹具，普通成员必须走真实申请/审批。此类测试不作为生产创建和资金闭环通过证据，不在正常运营统计中伪造组织或收益。生产迁移不插入示例圈和成员。

本轮先完成组织与权限、原契约适配、并发验证和后台查询。创建/升级/改名/解散/资金转入仍需业务确认和统一账本后单独验收。

补充消费者检查：圈主/管理员每次首次进入圈，会逐个游戏读取 build/getAutoBuildConfig 并关闭体力/矿石自动配置。本库未启用这些关闭功能，查询返回明确关闭状态，不开放收益或建设执行。
