# 异步响应与提交结果

本阶段源码和九项并发用例全部通过，纳入完整 172 项 Java 测试。严格 TypeScript/Vite 通过，当前开始部署后实际回归；此前 V12 一小时负载不包含该异步响应改动。

GameRequestDispatcher 返回 CompletionStage。接入仍先在固定业务线程池完成认证、解析和派发；若房间动作返回未完成阶段，工作线程立即返回，不使用 join/get 等待 JDBC。当前大厅/圈路由仍调用原同步业务方法后返回已完成阶段；尚未注册任何公开可玩房间路由。

每连接保持一个在途业务，后续请求留在原有有界 FIFO。全局 ReplyExecutor 默认最多 2048 张响应票据，覆盖等待结果、独立编码队列以及 EventLoop 排入 ACK 的完整区间，原始字节同时占用 32MiB 入站预算。两个专用编码线程、队列容量等于票据总数，已受理动作的结果不与普通业务提交争抢队列。编码回调只投递有界任务，不在房间邮箱或数据库 I/O 线程执行 JSON 编码。

结果到达后回原连接 EventLoop，先排入唯一普通 ACK，再放行此前暂存及本动作推送，然后处理下一条请求。断连会丢弃并释放尚未派发的输入，但已提交/状态未知的请求继续保留票据，直至结果到达；不能靠反复断连绕过全局在途上限。

明确的业务异常保留原 state，CompletionException 解包后仍只写一条普通响应。OutcomeUnknown、取消、超时、未分类异常、已确认动作的响应编码故障或响应执行器已停止时关闭连接并依赖持久状态恢复，不因响应投递失败谎报动作已回滚。未来房间适配必须把 STOPPED_OUTCOME_UNKNOWN 等未知提交明确映射到该分支；普通超时不能擅自完成为业务失败。

指标新增 game.reply.pending / active / queue。后续部署回归及大厅完整复测必须包含这些预算排空；原有负载报告只证明其当时版本，不外推为本阶段已验证。

这里保证单连接的派发/普通 ACK 顺序及其推送围栏，不提供跨连接的房间广播排序。未来公开房间适配仍须按永久房间 ID 和已提交事件序号串行投递，并处理重连快照与旧推送的衔接；不能认为不同请求的 CompletionStage 回调必定按数据库提交顺序运行。
