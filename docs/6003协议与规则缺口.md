# 6003 协议与规则缺口

当前完成源码核对、牌组/候选牌型/动作适配及内部出牌状态机，32 项相关单元测试和 1 项真实 MySQL 出牌/恢复组合测试通过，尚未注册网络路由，未开放建房或计分。不能将这些内部类视为已交付完整斗地主。

## 明确的客户端事实 E

- 普通牌 [suit,rank]：suit 为 1、2、3、4，rank 为 3 至 15；大小王为 [0,16]、[0,17]。两份原牌面素材合计 54 张有效牌；[0,0] 是展示占位。-1 癞子花色不属于标准 6003 的有效牌组。素材与 TS 的 SHA-256 见 evidence/landlord-6003-contract.json。
- 发送为原逻辑通道的平铺字段：api=room、c=gameMessage、tag=ready/score/jiabei/chupai/buchu/auto。score 按钮值为 0 至 3；jiabei 处理方法使用 0/1。chupai 的 outCards 是整数二元组数组，opCardType 为候选类型号，服务端必须重算并再次验证自有手牌和轮次。uid/sender 等请求字段不能作为角色身份。
- 类型号 1 至 13 依次为单张、对子、三张、三带一、三带二、顺子、连对、裸飞机、飞机带单、飞机带对、四带二、炸弹、火箭。普通顺子/连对/飞机的连续主体不含 2 和王。
- 标准状态按钮读取 currentState=0 等待、1 叫分、2 出牌。标准 table-class 的 updatejiabeiBtns 是空实现，不能因为 API/消息解析方法存在就启用标准玩法的加倍流程。
- 建房选项 cardType=4 对应 playNumber=6，cardType=8 对应 playNumber=12；cardType 不能直接解释为实际扣卡数量。aa 默认 true，圈/代开流程会隐藏付款选择并设为 false。界面静态标签为：6 局 AA 每人 1 / 房主总计 3，12 局 AA 每人 2 / 房主总计 6。这只是显示证据，没有证明扣费时点、付款授权或退款规则。

## 必须进一步确认的边界 U

1. 费用：确认实际扣费配置、AA 未到齐/换人、圈付款人与代开人/房主的关系，首次发牌还是建房扣费，未开局与中途解散退款，重试自然业务键。
2. 计分：底分、叫分与倍数的关系、炸弹/火箭与春天/反春天、倍数上限及封顶时点、总局数结束和积分范围。当前不发布候选默认值，不拿零分代替结算。
3. 飞机：客户端裸飞机条件含总张数偶数判断，因而排除三/五组裸飞机；单带/对带允许部分四张拆分且存在其他边界。当前分类器显式保留这些客户端限制作为兼容候选，不宣称它们就是原服务端地方规则。
4. 比较：客户端对飞机使用 getMinByFeiJi，会把某些四张翅膀也纳入最小主体；服务端候选按实际三张主体重算。两种行为的差异待确认，不在运行环境暗中放宽。火箭不能严格大于同一火箭，且单副实体牌不可能同时归属两家。
5. 托管/超时：auto 的发送与显示存在，具体托管策略、超时时间及断线/封禁后的牌局处理仍需规则版本约束；消息方法存在不等于自动开放。

## 已编写的实现边界

LandlordCard 校验实体编码；LandlordDeck 使用 SecureRandom 无放回发出三份 17 张及 3 张底牌，生产入口不接受种子或指定手牌。测试可在包内注入 Random，完整发牌只供私有持久事件与恢复，不直接广播。

LandlordPatterns 重算类型、比较主体及同长度序列，并提供不可变自有牌移除；LandlordWireActions 从原平铺 tag 转为类型化动作，严格检查整数、元组、重复与伪造 opCardType，不读取请求 uid。仍需要房间身份、阶段/轮次、事件持久化、私有视图、经确认的规则/计分以及原客户端多人联机验收。

RoomSnapshot/RoomJournal.Recovery 是内部私有状态，不能直接返回玩家或后台普通列表。直播期只可返回本人手牌、他人数量、已公开的出牌和适当阶段的底牌；完整历史回放权限和结束后展示范围需要专门适配。

## 内部出牌与持久重放（2026-11-07 03:47）

LandlordPlayEngine 从已确定地主的真实发牌结果开始，验证本局参与者、当前轮次、自有牌、牌型和压制关系；两次连续过牌后清空目标并由上一出牌者首出。不可变状态核对完整 54 张守恒、实体牌唯一、每位玩家已出牌次数与剩余牌数、目标/轮次以及真实空手胜者。托管仅记录开关，不擅自制定超时或自动出牌策略。

最后一张牌产生 ROUND_FINISHED 候选和持久事件，不按房间不存在处理。Outcome 只记录胜者、地主是否胜出、各人出牌次数、炸弹/火箭次数；没有 money/score 数值、临时收费或“零分结算成功”。调用方在完整经确认结算接入前不得开放该候选到生产路由。

LandlordPlayCodec 是带显式版本和字段白名单的私有编码。LandlordPlayPlans 重新核对同一动作能产生候选和事件，并绑定已认证身份，终局保存检查点。重放只处理保存的动作事件，不重新洗牌或记账。32 项单测中包含 400 个自然合法出牌测试牌局（有地主/农民两类胜出），每一步与重放状态比较；不是注入末手后直接宣布成功。

隔离 MySQL 组合测试先保存发牌检查点，真实邮箱每动作提交，中途关闭邮箱、取得新 owner_epoch、从检查点和事件恢复后继续出至空手，验证最终版本/事件/outbox 数量一致且没有资金命令。此夹具从“地主已确定”的阶段开始，没有验证叫分、收费、积分结算、原客户端完整推送或多人网页联机。
