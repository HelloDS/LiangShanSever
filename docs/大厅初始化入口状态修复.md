# 大厅初始化的实物入口状态查询

日期：2026-11-07。

## 问题与源码依据

玩家进入大厅时提示“方法传递错误”。原客户端 ApiState 将 state=-2 显示为该文字；该提示本身不包含具体路由。

原大厅侧栏构造流程固定调用 ActivityApi.getFreePhoneOpenType，实际发送 logic / freephone / getStatus，成功且 status==1 时才显示 mfkzssjBtn。来源为 Client/archive/8.137.34.190/client/platform/liangshan/154/main.min__q_009b646edacf3486.js，对应 Creator source-data 文件 c7d8a546d8b6c18e87d751fb1f8215746ea24b8b15eb3355fa69d97286e7a8af.txt。

现有 GameDispatcher 未处理 freephone/getStatus，会进入默认分支返回 state=-2。这是通过本地源码确认的确定性协议缺口；尚未从用户浏览器抓到此次提示所对应的完整报文，不能据此排除其他未接入路由。

## 修复

后端认证后的状态查询返回 {"state":0,"status":0}，表示查询成功、入口关闭。保留既有身份和会话检查，不开放 receiveCard 或其他实物执行接口。未修改 Creator 字段、界面或玩法，也未改变既有日志改动。

## 验证与运行状态

- LobbyAvailabilityTest 三项通过：关闭状态查询可用、未认证连接拒绝、实物领取仍拒绝。
- 执行离线 Maven reactor 的 game-transport 及依赖模块定向测试，BUILD SUCCESS。
- 执行离线 Maven package（跳过重复测试），生成新的 ruoyi-admin/target/ruoyi-admin.jar，BUILD SUCCESS。
- git diff --check 通过。
- 当前执行环境对 localhost 的连接返回 EPERM，进程查看也受限；未对运行中的旧服务执行停止或重启，避免停止后无法恢复监听。真实 HTTP/WS 联调及浏览器刷新验证待服务重启后执行。

## 本机应用修复

在 Sever 目录终端执行 scripts/stop.sh，正常退出后执行 scripts/run.sh。随后刷新 localhost:7456 并重新进入大厅。预期 freephone/getStatus 响应为 state=0、status=0，赠手机入口仍隐藏。

若仍出现相同提示，使用已开启的 SEND/RECV 日志定位下一条 state=-2 的普通响应及其对应请求；不以固定返回成功屏蔽未实现业务。
