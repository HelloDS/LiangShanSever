# 房间共享定时器

本阶段源码已编译，六项单元测试全部通过，纳入全套 146 项 Java 测试。未注册公开路由，没有发布业务超时、托管策略或投票规则。

RoomTimers 使用一个共享调度线程，按永久房间 ID 和固定用途保存待触发项。调用方提供已经冻结的延迟及深度不可变命令；基础设施仅接受 1ms 至 24 小时的技术范围，没有默选游戏超时时间。

用途包括轮次、托管、投票及等待到期，每个房间/用途至多一个待触发键；全局键容量显式配置。替换沿用该键的同一准入票据，满容量仍可替换原项，不能先删旧项再发现新项无法准入。替换过程中短暂存在旧/新调度对象，随后取消并立即移除旧任务；调度队列仍受有限键数约束。

触发只把包含 owner_epoch、version、round、phase 的命令重新投回原房间邮箱，不运行引擎或等待 JDBC。触发后由邮箱的独立命令预算接管，过期状态在邮箱拒绝，不能作用于下一局。取消仅匹配同一个 owner_epoch，旧连接/旧所有者的清理不能删掉新所有者的定时器。

关闭与注册通过生命周期锁串行，停止接收并取消尚未触发任务。已经交给邮箱的动作由邮箱处理；停机时生产者应先关闭，不能把尚未确认的事务当作已回滚。

已通过测试覆盖实际重新入邮箱、提交期间到期后拒绝旧版本、满容量替换、容量/取消/停止、旧 epoch 清理及 500 次取消后队列与容量不积累。这些是基础设施测试，不代表自然托管/投票流程已经完成。
