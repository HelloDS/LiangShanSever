# 亲友圈全量开发

本轮依据为 Creator 中的 club、diamond、clubpartner、clubbuild 模块及其实际请求消费者。用户要求持续开发、检查并在既有浏览器预览验收。体力、石材和开采按用户最新指示暂缓。

## 本轮规则

| 项目 | 取值与依据 |
| --- | --- |
| 新角色初始资产 | 用户确定为 1000 房卡、100 钻石，由初始奖励账本事务发放 |
| 创建圈 | 用户确定创建时从个人转入 100 张房卡 |
| 改名 | Creator 显示费用 50 张个人房卡，更名和扣费同一事务完成，重试或沿用当前名称不重复扣费 |
| 助理 | 用户确定最多 3 人 |
| 人数容量 | 用户确定上限 1000，沿用 Creator 的逐次扩容流程，默认初始 100 人 |
| 升级 | 用户授权采用默认值，每次消耗 100 张圈房卡，增加 100 人容量 |
| 兑换 | 用户确认圈内适用 1 钻石兑换 10 房卡，默认也支持 10 房卡兑换 1 钻石，无手续费，全部采用整数 |
| 圈资产权限 | 默认圈主操作，助理管理组织和成员 |
| 解散 | 用户确认无退款，关闭圈并保留余额及历史账目，存在未关闭房间时拒绝解散 |
| 圈内 6003 收费 | 沿用 Creator 展示的 6 局 3 卡、12 局 6 卡，首局实际发牌时从圈钱包扣一次，未开始不扣，已扣不退 |
| 自动开房 | 保存默认玩法即启用，保留一张与当前规则相同的未满等待桌。满员或开始后由服务端补桌，规则替换或关闭后保留已建桌 |
| 圈房间强制解散 | 圈主和助理可从圈大厅强制解散本圈房间，保留已经完成的局，当前未完成局不计分，首局已消费房卡不退 |
| 6003 超时 | 叫分、出牌默认 30 秒，托管轮到自己时 1 秒，初始等待和局间等待 30 分钟，解散投票 60 秒 |
| 6003 全不叫分 | 三人均不叫时，首位叫分者按默认 1 分成为地主，避免无限重发牌 |
| 6003 计分 | 默认底分 1，按实际叫分和炸弹、火箭、春天倍率结算，单个农民的分差上限为 64 |
| 合伙人审批 | 原申请没有邀请人字段，获授权的合伙人可审批圈内待处理入圈申请，成员归属由圈主或助理调配，退圈审批仍由管理员处理 |
| 建设 | 体力、石材和开采暂缓 |

## 实施进度

- 新角色奖励、建圈、改名、解散和助理上限已实现。建圈转入不足会回滚，同一创建者和首次名称的重发复用原创建记录，避免重复转卡。
- 个人和圈双向兑换、圈资产转入、容量升级已实现。玩家操作编号持久保存请求摘要和结果，与资金事务一起提交。
- Creator 已适配无退款提示、精确整数兑换、创建房间及经济操作的跨连接重试。新增房间编号后也会清除已结束创建意图。
- 合伙人的添加、解除、成员调配、业绩归属和审批授权已实现。归属在首局开始冻结，成员换组后不迁移历史战绩，清除数据只调整该成员的展示起点。
- 圈内 6003 创建、加入、准备、叫分、出牌、托管、局间准备、投票解散、首局扣卡和正式战绩已接入原 WebSocket 路由。逐次持久化、所有者围栏与恢复复用房间日志和邮箱。
- 默认玩法与服务端自动补桌已实现。自动开关按圈行锁串行处理，页面断开后仍会补桌。
- 录像从已提交事件生成，只有已关闭且包含实际终局的房间可读。参与者、圈主/助理和有对应历史归属的合伙人按范围读取。
- 圈战绩按每页 100 条使用时间和永久记录号翻页，相同时间的记录也可完整读取。网页已补翻页控件，处理读取失败、切换日期和关闭页面后的旧响应。
- 房间推送携带永久房间标识和提交版本，网页忽略晚到的旧状态。恢复旧快照时补齐这两个字段，原持久数据继续可读。
- 圈大厅删除按钮对应的 `room/forceDisbandRoom` 已接入，圈主与助理权限在房间提交事务中重新核验。
- 房主可在首局开始前踢出桌内其他玩家，释放座位和房间绑定。该操作保留被踢玩家的圈成员身份。
- 成员管理页可修改和清空备注，按 Creator 输入框上限保留 16 个 UTF-16 单元，由圈主和助理写入。
- 圈房间当前公开支持 6003，与架构方案第三版范围一致。Creator 另有 6008、6014、6038、6073 跑得快，6009 重炸斗地主，6060 张张牌，6061 凉山斗十四，6055 五子棋，6056 新凉山麻将和 6057 两房麻将，圈房间仍待接入。房卡和钻石的本地圈内流转已验证，外部支付及邀请分享渠道待单独验收。
