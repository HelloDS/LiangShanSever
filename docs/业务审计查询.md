# 业务审计查询

V13 源码与页面已编译，七项隔离 MySQL 集成用例及一项完成时刻测试通过；完整 172 项 Java、严格 TypeScript/Vite 通过。当前开始实际部署验收，尚未完成浏览器与 HTTP 复核。

V13 同时把管理请求键改为 ASCII 大小写敏感语义，避免不透明请求键被默认不区分大小写排序规则合并；已存键原样保留，不试图重构此前已合并的历史请求。

V13 为新管理命令的 admin_audit 增加 operation_id，唯一外键关联 admin_operation。命令副作用、审计和完成标记在同一事务内，审计或完成更新未确认影响一行即整体回滚；同一幂等键重试复用原命令和原审计。

历史记录不回填猜测编号。举报联系方式查阅仍独立记录审计，可以没有管理命令关联；页面显示“未关联”，不会据此断言执行失败。列表连接同时核对操作人、动作和目标，关联不一致时不会展示他人的完成状态。

新后台查询必须同时持有 game:audit:query 与实时平台数据范围。只持有指定圈范围不能读取全平台审计。筛选最多 31 个北京自然日、200 条一页，使用固定动作/目标/操作者/命令编号精确匹配；数据库查询两秒、事务三秒上限。数据库不可用为 503，不返回空的成功结果。

详情按已支持动作输出标量业务摘要白名单，数值转成精确字符串。任意原始 JSON、命令幂等键/摘要、结果载荷、会话凭据及举报联系原文都不输出；未知动作仅显示元数据并明确没有可展示摘要。时间转换为明确的 UTC Z 时间，由页面在本地格式化。

接口为 GET /game-admin/audit 及 /game-admin/audit/{id}。页面只有查询与详情，失败时清空旧列表/详情并隐藏分页。没有增加余额编辑、补偿命令或审计删除入口。


本地实际验收：HTTP 五项通过，浏览器仅审计授权、精确命令筛选、新命令会话版本 0→1、历史未关联提示和撤权下一请求拒绝均通过；临时账号与范围已清理。证据 audit-smoke.json / audit-browser.json。
