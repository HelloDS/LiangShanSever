# 房间日志与恢复边界

本阶段新增内部持久化实现及只读后台，没有注册建房、入房、游戏动作或解散写路由。V10 不写示例房间。6003 的费用、结算与封顶规则仍待确认，不能将内部计数器夹具当成真实对局。

## 事务连接与锁

RoomTransactionBoundary 在数据库 I/O 线程先选择 ROOM，再开启唯一事务管理器的 TransactionTemplate；拒绝从已存在事务调用。房间池最多 8 个连接，普通池最多 16 个连接。它们共用路由 DataSource，但一笔房间事务只使用 ROOM 的一个物理连接。钱包 REQUIRED 和 outbox MANDATORY 加入此连接，任何阶段失败均整体回滚。路由上下文在 finally 恢复。

房间提交先锁凭据、角色和账号以验证身份，再锁永久 room_id 的运行行。批量钱包先按业务键顺序预占全部事务记录，再按主体/币种顺序锁全部涉及账户，最后按原业务输入顺序记账。不能循环调用单笔钱包并让每笔自行决定锁顺序。

事件以 (room_id,event_seq) 唯一，摘要覆盖旧/新状态哈希、epoch、版本、局号、阶段、事件、原始发生时间、规则/引擎版本、身份、占座和账本意图。稳定业务键引用永久 room_id，不引用可复用房号。全量状态只在显式检查点更新；每次动作仍写版本和事件。

快照和事件采用带 JSON_VALID 约束的 utf8mb4_bin LONGTEXT，保存规范化后的原始数字。实际 MySQL 8.4 的 JSON 二进制转换会把文本中的 0.123456789012345678901 变成 0.12345678901234568，不能用于要求精确摘要往返的私有恢复材料。规范化以 BigDecimal/大整数处理数值，逐层排序对象键，线上报文序列化不变。

## 提交确认与恢复

工作体中的已知校验拒绝在事务回滚后返回 NOT_COMMITTED。连接异常、提交异常以及 afterCommit 异常保持未知，即使异常类型看起来是约束错误，也不能擅自认定未提交。邮箱暂停该房间，resolve 锁运行行并查询同一事件摘要，确认结果后安装状态或丢弃候选。候选发生时间只捕获一次，重试不重新生成。

取得所有权先验证引擎版本、检查点摘要、连续事件链和恢复预算，然后递增持久 owner_epoch。最多重放 2048 条、8 MiB 事件；超限或缺失时拒绝接管，不跳过事件。RoomReplay 只执行纯计算，逐条验证恢复后的状态哈希，不再发牌、记账或写 outbox。旧 epoch 的邮箱和迟到回调不能覆盖新所有者。

player_room_binding 的 UID 主键约束跨房间唯一占用；同房间座位也唯一。关闭在同一事务释放活跃占用和房号，历史 room_id、事件和参与者记录保留。复用房号创建的是全新永久实例，旧重试不得释放新实例的号码。

## 消费与查询

ROOM_EVENT_COMMITTED 的 consumer_receipt 与事件计数投影同事务提交。重复投递读取原收据，不重复计数；失败回滚收据。该投影仅表示实际持久事件数量，不代表对局、终局、耗卡或奖励资格。规则版本与发生时间从真实事件核对，乱序消费不降低已处理最高版本。

后台房间页只按菜单权限及独立 PLATFORM/CLUB 数据范围查询元数据和公开参与者。日期最多 31 天、每页最多 200 条，SQL 与事务均有超时；故障明确失败，不伪装成空列表。快照、事件载荷、手牌和随机发牌结果不进入此接口。尚无强制解散或资产按钮。
