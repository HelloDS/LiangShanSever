# 每日账本核对

2026-11-07 05:15：V11/V12 已部署至本地环境。新增 11 项隔离 MySQL 集成测试与 4 项 worker 测试通过；完整 Java 测试共 146 项通过，严格 TypeScript/Vite 构建通过。真实 HTTP 六项验证及只读浏览器验收通过，见 evidence/reconciliation-smoke.json、evidence/reconciliation-browser.json。

## 核对口径

对个人、亲友圈及系统清算的房卡/钻石账户，核对“期初余额 + 已记账变动”与当前可用/冻结额。每个账户使用独立、限时的 REPEATABLE READ 一致性读；结果反映该账户实际检查时刻，不是假设整库在每日零点的历史余额。

开始时冻结个人 UID 和亲友圈 ID 的扫描上界，按主体/编号/币种作有界 keyset 扫描，测试账户/测试圈排除。开始后新建账户留给下一次核对，避免不停增长的扫描。系统清算账户也检查，负数不被误认成玩家资金。

发现差异只保存应有值、实有值、账本位置和检查时间，最终状态为“发现差异”。不修正余额、不生成补偿、不删除或改写流水，也不把技术失败记成一致结果。

## 任务与恢复

V11 的每日任务按北京时间核对日期唯一。来源明确为 SYSTEM 或真实管理员，系统任务不冒用管理员 ID。一个专用线程在普通 Druid 池执行，不占房间邮箱或房间事务池；每轮至多 32 个账户，软预算一秒，每个账户事务最长五秒，轮询仅保留一个未来调度项。

30 秒持久租约及随机 token 确定当前处理者。账户结果、计数和游标同事务推进；失败整笔回滚，游标不越过未检查账户。提交结果未知时重新读取持久游标继续，唯一明细主键防止重复登记。新租约持有者接管后，旧处理者不能推进、回退或清除它的状态。

连续失败有界退避，五次未成功推进后停止为 FAILED。人工重试保留原任务、结果、游标和累计失败数，需独立权限、平台数据范围、原因、幂等键和审计；只能继续未完成部分。已完成核对不会因点击按钮重新运行。

默认北京时间 04:15 后创建本日任务，停机期间不伪造历史检查；迟启动执行实际启动后的核对并保存真实时间。GAME_RECONCILIATION_ENABLED=false 暂停自动工作，原任务仍保留。小时和分钟可通过 GAME_RECONCILIATION_HOUR / GAME_RECONCILIATION_MINUTE 配置。

## 后台与可观测性

账本核对页支持最多 31 天/200 条查询、状态和进度、默认差异明细及可切换的一致结果。所有查询要求独立菜单权限及平台数据范围，创建与重试分别鉴权。资产数值按字符串展示；故障明确显示查询未完成，不以零数据代替。

指标包含已确认检查数、失败数、检查耗时、待执行/处理中/失败任务数量及采样可用状态。采集失败为未知，不表示零；数据库任务和明细是检查数量的权威事实。现阶段保留任务与明细，没有未经确认的自动清理策略。

已通过测试覆盖：每日并发唯一、正式/测试账户范围、新账户上界、零余额事实、真实差异不修复、并发领取/到期围栏、晚期游标失败整体回滚、五次失败与审计重试、并发记账的一致性读、提交结果丢失后的持久恢复，以及调度、停止与未知指标。


后续待验证补强：告警采样也纳入 DONE_WITH_ISSUES，指标表示已保存的差异记录数量，不宣称当前余额仍有同样差异；没有未经审计的“已解决”按钮或自动补偿。停止后的旧调度代次不能向新代次排入额外任务。新增两项 worker 用例已通过，包括旧调度线程在停止等待到期后才返回的实际并发场景；完整 Java 累计 172 项通过。
