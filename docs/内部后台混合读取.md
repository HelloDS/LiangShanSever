# 内部后台混合读取

旧夹具短测已通过；完整测量与新十路并行夹具的结果分别记录，不混算通过范围。

RoomStorageLoad 可显式设置 ROOM_LOAD_ADMIN_READERS=10，在同一个隔离 Spring Boot 进程中加入后台读取。测试数据库名必须为 room_load；只在其新库中初始化随机管理员密码，建立十个独立 JWT。用户名/密码/令牌仅在测试进程内存，不保存到报告或日志，不接触主运行库管理员。

旧冻结夹具每十秒由一个共享 tick 向两线程、十等待项的有界 HTTP 池投递十次查询，每会话单在途。它建立十个独立 JWT，但最多两个 HTTP 查询同时执行，且原延迟从工作线程开始计时，不能视为十并发读取。

后续源码改为十个预启动的固定 HTTP 工作线程，等待队列仍有界，每会话仍只允许一个在途。报告增加 httpWorkers、peakConcurrentQueries、latencyIncludesClientQueue，延迟从 tick 准入开始计时；必须实际观察到十路同时执行、零失败且排空后才可判定这组目标通过。新夹具已编译并完成独立两分钟测量，实际峰值十路 HTTP，不能追溯改变旧结果。房间列表检查实际房间总数与分页大小；指定玩家查询检查 UID；看板检查测试身份未进入正式注册/登录统计。所有调用经过实际 HTTP、JWT 与平台数据范围链，不通过内部服务冒充后台请求。

记录后台请求数量、成功/失败/忙碌/未完成、P50/P95/P99/最大延迟；后台读取 P95 上限 300ms，零失败/零跳过/排空是该模式通过条件。新夹具内部持久确认收紧为 P95≤50ms、P99≤100ms，仍不等于已经测量完整帧到输出队列的时间；原有动作吞吐、outbox 消费及恢复判定保留。旧夹具曾使用内部 P95 300ms 的保护阈值，其短测 PASS 不等于满足方案动作目标。一次失败不通过重发或删除原始结果掩盖。

这是内部机械出牌持久写入与后台房间/玩家/看板读取的组合，没有经 WS 发送牌局动作，不包含费用、最终计分、圈排序、导出或 WSS。不能将它当成方案完整混合牌局验收。默认值仍为零后台会话，既有冻结基线完全不变。
