# 内部后台混合读取

测试工具已编写，尚待编译和独立执行，不是通过记录。

RoomStorageLoad 可显式设置 ROOM_LOAD_ADMIN_READERS=10，在同一个隔离 Spring Boot 进程中加入后台读取。测试数据库名必须为 room_load；只在其新库中初始化随机管理员密码，建立十个独立 JWT。用户名/密码/令牌仅在测试进程内存，不保存到报告或日志，不接触主运行库管理员。

每十秒由一个共享 tick 向两线程、十等待项的有界 HTTP 池投递十次查询，每会话单在途。房间列表检查实际房间总数与分页大小；指定玩家查询检查 UID；看板检查测试身份未进入正式注册/登录统计。所有调用经过实际 HTTP、JWT 与平台数据范围链，不通过内部服务冒充后台请求。

记录后台请求数量、成功/失败/忙碌/未完成、P50/P95/P99/最大延迟；P95 上限 300ms，零失败/零跳过/排空是该模式通过条件。原有动作吞吐、延迟、outbox 消费及恢复判定同时保留。一次失败不通过重发或删除原始结果掩盖。

这是内部机械出牌持久写入与后台房间/玩家/看板读取的组合，没有经 WS 发送牌局动作，不包含费用、最终计分、圈排序、导出或 WSS。不能将它当成方案完整混合牌局验收。默认值仍为零后台会话，既有冻结基线完全不变。
