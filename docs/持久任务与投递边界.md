# 持久任务与投递边界

目前接入玩家管理命令的 `PLAYER_REVOKED` 和房间日志事务的 `ROOM_EVENT_COMMITTED`。前者锁定账户、增加会话版本、写操作结果/审计/outbox，后者写房间版本/事件、需要的占座/钱包以及 outbox，分别在同一 Spring 事务及 Druid 连接提交；任何一步失败整体回滚。业务重试不重复副作用，事件按业务键和类型唯一，摘要不同则拒绝。

提交后监听器立即按版本关闭旧连接；持久 worker 再按原事件处理，覆盖提交后进程中断的投递窗口。重复事件只能撤销更旧会话，不能关闭已经按新版本登录的连接。数据库里的账户版本是权限撤销事实，通知不是唯一鉴权措施。

V15 房间消费者先按事件 ID 与当前租约令牌加锁，在同一普通池事务提交 consumer_receipt、事件数量投影和最终 DONE。任何晚期失败均整体回滚，旧租约在副作用前拒绝；与旧版分两次事务消费后完成相比，去掉一个独立提交。重复投递不重复计数，乱序处理不降低最高版本。该数量是持久状态事件数，不是终局、积分、耗卡或领奖资格。四项真实数据库组合用例及 worker 路由用例通过；性能仍以对应负载证据为准。

## 领取与重试

- 领取为独立 `READ COMMITTED` 事务，使用 `FOR UPDATE SKIP LOCKED`；默认可重复读下曾由真实并发测试发现状态索引间隙锁死锁，修正后测试通过。
- 每批最多 16 条，当前租期 60 秒；4 个处理线程、等待队列容量 16、总计最多 18 条已领取在途票据。轮询只有一个未来调度项，失败时刻保存在数据库，不为每条事件创建定时器。
- 锁定待领 ID 后一次批量更新、一次批量读取，不逐条进行两次 SQL。批次共用新 token，完成/失败仍用每个事件 ID 与 token 的组合围栏；批次读取或数量不完整时整体回滚租约和尝试次数。并发领取互斥、旧租约拒绝及批次晚期失败回滚已通过真实 MySQL 验证。
- 每次领取增加当轮和累计次数。失败指数退避为 1、2、4、8 秒，最多领取 5 次；最后一次失败或最后一次租约过期进入 DEAD。完成和失败更新都带租约令牌，失去租约的旧 worker 不能覆盖新处理结果。
- 人工重试仅接受 DEAD，要求 `game:outbox:retry`、平台数据范围、原因和 Idempotency-Key。保留事件 ID/业务键、累计尝试数及审计；重新入队与最终处理完成分别呈现。
- 停机先停止领取，允许已有处理等待最多 5 秒；未完成任务依靠持久租约恢复。数据库异常不会把任务标成成功。

## 监控与查询

后台“持久任务”按北京时间日期范围查询，最多 31 天、单页最多 200 条；默认只显示元数据和固定错误代码。查看需 `game:outbox:query` 及平台数据范围。积压查询设置 2 秒 SQL 超时；三个状态分支强制使用覆盖索引，避免 DONE 历史增长拖慢少量积压计数。完成/失败标记事务限时五秒。

指标包括 `game.outbox.inflight`、completed、failed、lease.lost、poll.failed、ready、claimed、dead、oldest.seconds 和 backlog.available。积压样本约每 10 秒刷新；采集失败返回不可用，数量为 NaN，不以零掩盖未知。oldest 为所有未完成（含 DEAD）事件的最早发生时间。

新增领取与处理时长 timer、领取批次大小 summary；房间事务 timer 包含取得所有者、提交和结果核对，不将它冒充单一网络动作的端到端耗时。

## 尚未覆盖

这是可重复投递加幂等处理，不声称 WebSocket 端到端 exactly-once。圈推送目前仍在普通 ACK 排队之后投递，数据库消息/成员查询用于恢复；未将其直接迁入 worker，以免破坏原客户端 ACK 与推送顺序。正式房间结算及其活动/排行榜统计、回放归档和玩法奖励每日任务尚未接入，不能据此声称整套结算事件闭环已经完成。

任务与审计当前保留，不擅自删除历史或设置未经确认的业务保留期限。后续归档应先记录容量、恢复和审计需求。
