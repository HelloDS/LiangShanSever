# 房间邮箱与提交边界

当前为服务端内部基础设施，尚未注册公开房间路由，也没有创建运行库房间。6003 收费/结算规则未确认，不能把该底座称为可玩的完整斗地主。

`RoomMailboxes<S,C,E>` 将永久 UUID roomId 映射到固定分片；同房间的动作、内部定时器和完成消息串行执行。不可变快照带 ownerEpoch、version、round、phase，房号不作为邮箱或事件主键。调用方须先在数据库取得所有权并恢复已提交状态，再 register。

每分片普通命令预算最多 4096，覆盖普通队列、等待数据库的房间内队列和结果通知；每房间最多 64 个准入动作。房间数与 I/O 线程/队列也有显式上限。一个房间最多一个提交；完成/核对消息使用每房间预留的独立容量，普通预算耗尽时仍能安装已提交状态。每 8 个完成消息让出一次普通动作机会。

引擎只计算候选状态与事件，I/O 在线程池调用 RoomPersistence；分片中没有 Future.get/join 或 JDBC 等待。COMMITTED 后才发布候选状态及结果；NOT_COMMITTED 丢弃候选；UNKNOWN 或存储异常保留原状态、暂停该房间、在数据库结果确认后推进。每个未确认提交最多一个有界重试调度项，重试仍回原分片。失去所有者时关闭旧邮箱，迟到消息不能安装到新 ownerEpoch。

定时器携带创建时的 epoch/版本/局号/阶段，重新入邮箱后逐项核对，过期直接拒绝。结果通知在独立有界线程池完成，准入票据在通知结束后释放；接入层回调须仅排队非阻塞网络操作。停止时返回“结果未知/服务停止”，不把未确认事务返回业务成功或已回滚。

S、C、E 必须是深度不可变值。RoomSnapshot 包含内部状态，禁止直接作为玩家报文；玩法适配器须按观看者生成私有手牌和公共计数。当前没有生产指定手牌或任意状态注入接口。

13 项确定性并发单元测试使用整数状态及可控持久化替身，验证串行版本、提交前不可见、同分片其他房间推进、房间/分片准入、完成预留、未知结果确认、已知回滚、存储异常、过期定时器、所有者切换、慢通知隔离、停机释放及发生时间在重试中固定。真实 MySQL 实现及验证见 `房间日志与恢复边界.md`；这些测试不代替 6003 规则或旧客户端联机验收。
