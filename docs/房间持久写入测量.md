# 隔离房间持久写入测量

这组工具测内部 6003 单张/过牌状态提交、测试换局及其 outbox 消费。没有 WS、叫分、费用、积分结算或自然网页多人联机，不作为方案中的完整混合牌局容量验收。

工具位于测试源码，不打入运行 JAR。显式设置 RUN_ROOM_STORAGE_LOAD=1 后，新建固定镜像的 Testcontainers MySQL/Redis，只允许数据库名 room_load；运行库不写夹具。每房间三名持久测试身份，从已确定地主的真实随机发牌开始，每次单张或过牌都校验并走真实邮箱/数据库事务。出完后按测试规则轮换地主，保存新的私有发牌检查点；这不是生产叫分或结算规则。

运行前复制已编译类、资源和全部依赖，并记录 SHA-256 与提交。空 classpath 项不得当工作目录复制，编译目录限定为 target/classes 或 target/test-classes；3 项 Python 路径回归测试通过。冻结的 Java 进程不会读取随后改写的 target/classes。

后续版本将 outbox 领取从逐条 SQL 改为批量更新/读取，保留事件 ID+租约围栏、回滚和 18 条在途上限。工具额外要求测量采样的最老 outbox 不超过 10 秒；这是本组内部测量预算，不是新增业务规则。需要在无其他构建/测试的独立测量中验证效果。

trial-3 的 120 秒测量通过新条件：23999 次提交、零错误/忙碌，P95 18.551ms、最长 123.550ms，最老 outbox 最大采样 2.313 秒，测后队列与持久消费排空。随后使用同一冻结快照开始一小时测量，不拼接短测时长。

本次一小时测量约 35 分钟后出现 outbox 告警，普通提交仍推进。只读诊断见 evidence/room-storage-query-diagnosis.json：旧聚合语句在约 47.6 万行估计数据上采用 type=index 全索引扫描；分成状态等值分支后的计划为 ref。一次实际计数时 READY 为 62043、CLAIMED 14、DEAD 0。该实例 buffer pool 实际为 128 MiB。一次单独聚合探测与初次告警接近，不能只凭时间先后认定唯一原因。

测量期间没有变更运行索引、线程、内存参数或字节码。本轮继续保留完整结果；源码中的 V12 覆盖索引、等值统计和四消费线程尚待编译/回归及从头复测。总在途上限仍为 18，不以无界排队增加吞吐。后续报告还单独记录消费错误/失租/轮询错误及线程忙碌数，不能只看事后排空。

另补充完成/失败事务的五秒超时；四线程、十八条在途，后续租期调整为六十秒预留正常排队余量，仍依赖事件 ID/token 围栏和消费者幂等保证安全。连接池等待、提交和进程暂停不等同于事务超时保证，超过租期仍须按原事件安全接管。该变更没有作用于当前冻结测量，待真实锁等待超时用例及后续负载验证。

约 55 分钟时额外做了一次有一致性快照的只读故障观测，见 evidence/room-storage-observation-55m.json。200 个房间的运行版本合计 670178，与 READY 125984、CLAIMED 13、DONE 544181、DEAD 0 的任务总和一致；投影 544182 比 DONE 多一条，符合消费事务已提交、完成标记尚在途的窗口。该观测不是直接 COUNT(room_event)，不能冒称逐条全表审计。数据库目录当时约 5.02 GB，包含 binlog/redo/索引等，且只到约 55 分钟；这些额外诊断查询也参与了负载，不能作为无干扰通过证据。

## 输出与限制

报告保存实际提交数、单张/过牌/测试换局数、延迟、慢提交的时间与类别、JVM/GC/SQL 池、队列和 outbox 样本；结束后核对事件、DONE、consumer_receipt、投影数量与预算排空，再测十个房间的恢复。全程无钱包命令。

数据库目录字节数包含表、索引、binlog、redo、临时文件及系统库；information_schema 大小与行数是估计值，不能直接换算成精确单事件写放大。堆/非堆采样不能代替回收后存活分析或 24 小时稳定性。长期测量完成前不宣称达到 60 分钟目标。
